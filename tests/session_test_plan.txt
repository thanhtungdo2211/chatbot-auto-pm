

## 1. QA thông tin (project / task / member)

### TC01 – Đếm số project

* **Tiền điều kiện**

  * Workspace có sẵn 5 project (ví dụ).
  * Không có session nào đang mở (`session=None`).

* **Bước thực hiện**

  1. User gửi: **“Có bao nhiêu project?”**
  2. Hệ thống gọi API đếm project trong workspace (vd: `GET /projects`).
  3. Agent sinh câu trả lời dựa vào tổng số project.

* **Kỳ vọng**

  * Bot trả lời dạng: **“Hiện tại có 5 project trong workspace.”**
  * Không có lỗi parse/LLM.
  * `session` vẫn = `None` (không mở luồng mới).

## 2. Tạo project (session create_new_project)

### TC08 – Upload file JSON hợp lệ

* **Tiền điều kiện**

  * User upload file JSON, nội dung chứa:

    * `project_name` / `name`
    * `identifier`
    * danh sách `tasks` (mỗi task có title, description, v.v.)
  * `session=None`.

* **Bước**

  1. User upload file + nhắn: **“Tạo project từ file này”**.
  2. Bot parse file JSON:

     * Trích `name`, `identifier`, `tasks`.
  3. Bot set session: `session.type = "create_new_project"`, lưu tạm dữ liệu trong session.
  4. Bot hỏi xác nhận:

     > “Mình sẽ tạo project ‘Demo’ với 10 task, bạn xác nhận ‘có/không’?”

* **Kỳ vọng**

  * Parse file thành công, không lỗi JSON.
  * `session` chuyển sang `create_new_project` với payload đúng.
  * Bot hỏi xác nhận trước khi gọi API tạo.

---

### TC09 – File thiếu dữ liệu (không có name/identifier/tasks)

* **Tiền điều kiện**

  * File JSON user upload thiếu toàn bộ các trường `name`/`identifier`/`tasks` hoặc không parse được.
  * `session=None`.

* **Bước**

  1. User upload file + nhắn: **“Tạo project từ file này”**.
  2. Bot cố gắng parse.
  3. Không tìm thấy đủ dữ liệu project.

* **Kỳ vọng**

  * Bot trả lỗi rõ ràng:

    > “File không hợp lệ hoặc không tìm thấy thông tin dự án (name/identifier/tasks). Vui lòng kiểm tra lại file.”
  * Không mở session (`session=None`).

---

### TC10 – Xác nhận “có” sau khi tạo project

* **Tiền điều kiện**

  * Đang có session: `create_new_project` với payload project + danh sách task đã parse đúng.
  * Bot vừa hỏi: “Bạn có muốn tạo project này không?”

* **Bước**

  1. User trả lời: **“Có”**.
  2. Bot gọi API:

     * `create_project` với name/identifier.
     * Sau khi thành công, gọi `create_issue` cho từng task (đếm số task).
  3. Bot nhận lại URL project (vd: `/projects/demo/board`).

* **Kỳ vọng**

  * Tất cả API tạo project + task gọi thành công (đúng số lượng).
  * `session` được **clear** (`None`).
  * Bot trả kết quả:

    > “Đã tạo project Demo với 10 task. Bạn có thể truy cập tại: <URL>”

---

### TC11 – Xác nhận “không” sau khi tạo project

* **Tiền điều kiện**

  * Session `create_new_project` đang active.
  * Bot đang chờ confirm.

* **Bước**

  1. User trả lời: **“Không”**.
  2. Bot không gọi bất kỳ API tạo project/task nào.
  3. Bot xoá session.

* **Kỳ vọng**

  * Không có thay đổi dữ liệu trên Plane.
  * `session` chuyển về `None`.
  * Bot trả lời:

    > “Đã hủy thao tác tạo project.”

---

### TC12 – Đổi chủ đề giữa chừng trong session create

* **Tiền điều kiện**

  * Session `create_new_project` đang active, vừa hỏi “Bạn có muốn tạo project này không?”.
  * Hệ thống đang chờ confirm.

* **Bước – Nhánh 1 (user hỏi thời tiết, chọn không hủy)**

  1. User gửi: **“Thời tiết hôm nay thế nào?”**
  2. Bot **không** xử lý ngay câu hỏi thời tiết, mà hỏi lại:

     > “Bạn đang trong luồng tạo project. Bạn có muốn hủy thao tác này để chuyển sang câu hỏi mới không (có/không)?”
  3. User trả lời: **“Không”**.
  4. Bot giữ nguyên session, nhắc lại câu hỏi confirm:

     > “Ok, chúng ta tiếp tục. Bạn có muốn tạo project này không (có/không)?”

* **Kỳ vọng Nhánh 1**

  * Session **không** bị clear.
  * Bot không trả lời thông tin thời tiết.
  * Vẫn tiếp tục luồng tạo project.

* **Bước – Nhánh 2 (user chọn có hủy)**

  1. Từ bước 2 ở trên, user trả lời: **“Có”**.
  2. Bot clear session `create_new_project`.
  3. Bot chuyển sang xử lý intent mới: câu hỏi thời tiết.

* **Kỳ vọng Nhánh 2**

  * `session=None`.
  * Không gọi API create_project.
  * Bot trả lời thông tin thời tiết bình thường.

## 3. Cập nhật project / task / member

### TC13 – Đổi mô tả project hợp lệ (confirm “có”)

* **Tiền điều kiện**

  * Project “Demo” tồn tại, có field `description`.
  * `session=None`.

* **Bước**

  1. User: **“Đổi mô tả project Demo thành ‘Dự án demo cho khách A’.”**
  2. Bot phân tích:

     * intent = update project
     * field = description
     * project = Demo
  3. Bot tìm project Demo qua API → tồn tại.
  4. Bot set session `update_existing_information` với payload (project=Demo, field=description, new_value=…).
  5. Bot hỏi xác nhận:

     > “Bạn xác nhận đổi mô tả project Demo thành ‘Dự án demo cho khách A’ chứ (có/không)?”
  6. User: **“Có”**.
  7. Bot gọi API `update_project` với description mới.
  8. Sau khi thành công, clear session.

* **Kỳ vọng**

  * Project Demo có description được cập nhật đúng.
  * `session` reset về `None`.
  * Bot trả:

    > “Đã cập nhật mô tả project Demo thành công.”

## 4. Assignment (giao task)

### TC23 – Assign khi còn task chưa assign

* **Tiền điều kiện**

  * Project “Demo” tồn tại.
  * Có ít nhất 1 task trong Demo có `assignee = None`.
  * Trong project Demo có danh sách member khả dụng.
  * `session=None`.

* **Bước**

  1. User: **“Giao task trống trong Demo cho team.”**
  2. Bot hiểu intent = assignment:

     * Project = Demo
     * Task target = các task chưa có assignee.
  3. Bot liệt kê các task chưa assign, và list member candidate.
  4. Bot có thể hỏi:

     > “Demo có 3 task chưa assign: Task A, Task B, Task C. Bạn muốn giao cho ai? (ví dụ: [alice@example.com](mailto:alice@example.com))”
     > **hoặc** gợi ý auto-assign (tùy design).
  5. User: **“Giao hết cho [alice@example.com](mailto:alice@example.com)”** hoặc **“Có”** với đề xuất của bot.
  6. Bot gọi `update_issue` set `assignee` cho các task trống.
  7. Clear session.

* **Kỳ vọng**

  * Tất cả task trống được gán assignee đúng.
  * `session=None`.
  * Bot báo số task đã assign, kèm người được giao.

  2. Bot hỏi lại:

     > “Bạn đang trong luồng giao task. Bạn có muốn hủy luồng này để chuyển sang câu hỏi mới không (có/không)?”
  3. Nếu **“Không”**:

     * Giữ session assignment.
     * Bot nhắc lại:

       > “Ok, ta tiếp tục giao task. Bạn muốn giao các task trống cho ai?”
  4. Nếu **“Có”**:

     * Bot clear session assignment.
     * Bot trả lời câu hỏi thời tiết.

* **Kỳ vọng**

  * Hành vi đúng như logic hủy/tiếp tục.
  * Không vừa assign vừa trả lời chủ đề khác.

### TC27 – Assignment sau khi thêm member mới

* **Tiền điều kiện**

  * Project “Demo” tồn tại.
  * Workspace có member mới `bob@example.com` vừa được add vào project Demo (qua testcase kiểu TC18).
  * Có task chưa assign trong Demo.
  * `session=None`.

* **Bước**

  1. User: **“Assign task trống trong Demo cho team.”**
  2. Bot gọi API:

     * Lấy danh sách task chưa assign.
     * Lấy danh sách member của project Demo (đã bao gồm [bob@example.com](mailto:bob@example.com)).
  3. Bot gợi ý danh sách candidate:

     > “Các member trong Demo: [alice@example.com](mailto:alice@example.com), [bob@example.com](mailto:bob@example.com), … Bạn muốn giao cho ai?”
  4. User: **“Giao cho [bob@example.com](mailto:bob@example.com).”**
  5. Bot gọi `update_issue` set `assignee=bob@example.com` cho các task trống (theo logic).
  6. Clear session.

* **Kỳ vọng**

  * Danh sách candidate **có chứa** member mới [bob@example.com](mailto:bob@example.com).
  * Task được gán cho [bob@example.com](mailto:bob@example.com) thành công.
  * `session=None`.
